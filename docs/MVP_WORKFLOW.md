# MVP 工作流：客户访谈整理与跟进助手

> 状态：当前选定的 MVP 假设 v0.1。用户认可该场景作为起点；目标用户的实际痛点、任务频率和可量化价值仍需用真实任务验证。

## 目标用户与任务

- **目标用户假设：** 为制造业客户提供数字化转型、出海或相关咨询服务的项目/交付人员。
- **触发事件：** 完成客户访谈、需求沟通或项目阶段性讨论后，需要把零散对话整理成团队可执行、可跟进的记录。
- **待完成任务：** 从访谈材料中提炼客户现状、需求、风险和下一步，并准备一份可以由项目人员审核的客户跟进内容。
- **失败代价：** 误记客户事实、把推测写成承诺、错配负责人或遗漏重要问题，会损害后续交付与客户信任。因此首版输出必须可追溯并由人审核。

## MVP 流程

1. 用户选择或粘贴一份会议转写/访谈笔记，并输入必要的项目背景，例如客户行业、产品、项目阶段和本次沟通目标。
2. Agent 检查输入是否足以完成整理；缺少信息时提出少量具体问题，用户可以跳过，跳过项须保留为未知。
3. Agent 生成一份跟进简报草稿，按以下部分组织：
   - 客户现状：仅列材料明确提供的情况；
   - 明确需求：客户直接表达或材料直接支持的需求；
   - 潜在问题与机会：注明这是分析/推断，并给出依据；
   - 待确认问题：记录信息缺口、冲突和需要客户澄清的事项；
   - 下一步行动：只记录材料明确提出的行动；负责人和期限缺失时标为待确认；
   - 跟进邮件草稿：用于内部审核，不自动发送。
4. 用户逐项查看来源、修改或删除内容，确认简报可供团队使用。
5. 用户导出 Markdown 或复制内容。首版不向邮件、CRM、日历、任务管理器或客户系统写入数据。
6. 发生解析或生成错误时，保留原始输入和已完成的草稿部分，说明失败阶段并提供重试或手动编辑路径。

## 证据与内容规则

- 直接事实、Agent 分析/推断、待确认信息必须使用不同标签或结构字段表达。
- 有段落、页码或时间戳时，重要内容关联到输入材料的具体位置；若输入格式无法提供定位信息，至少展示所依据的原文摘录或来源文件名。
- 不虚构公司背景、客户意图、预算、时间表、负责人、客户承诺或法规/市场结论。
- 材料冲突时并列指出冲突来源，不自行选择一个版本作为事实。
- 邮件草稿里的新信息必须能追溯到用户输入；无法确认的承诺不得写成确定语气。

## 首版范围

### 包含

- 手动粘贴文本，或上传一种易于解析的访谈文本格式；优先用 Python 常见文档解析库完成输入处理，不因 Agent 框架限制数据格式。
- 用户补充少量项目上下文。
- 单次生成结构化简报和跟进邮件草稿。
- 用户在导出/复制前审核和编辑。
- 显示输入资料、来源依据、未知项和失败状态。

### 暂不包含

- 自动录音、语音转写、会议机器人或实时会议接入。
- 自动访问整个客户文件夹、邮箱或企业知识库。
- 自动发送邮件，或自动创建/更新 CRM、待办、日历和项目记录。
- 多客户批处理、定时运行、团队权限系统、多 Agent 编排和无人值守执行。
- 对客户意向、商机概率、市场机会或合规情况作确定性判断。

如果真实用户样本证明某项排除能力是首条流程的必要条件，再通过决策记录调整范围。

## 首轮验证与验收

### 验证样本

先收集 5–10 份真实且获准使用、或经过脱敏的访谈记录。记录人工处理基线，再用 Agent 处理同一批材料；样本只用于发现问题，不用于泛化结论。

### 每份任务记录

- 人工基线耗时与 Agent 辅助后的总耗时；
- 用户修改、删除或补充的字段及原因；
- 事实错误、遗漏、虚构信息、错误归因、负责人/期限误判等问题；
- 用户能否快速找到关键结论的原始依据；
- 用户是否愿意在下一次访谈继续使用。

### MVP 验收条件

- 用户能够提供访谈材料和必要项目背景，并获得上述结构的完整草稿。
- 重要结论能够回到输入材料；材料没有提供的信息明确标记为未知或待确认。
- 用户可以编辑和导出草稿，且系统不会未经确认执行外部写操作。
- 生成失败时输入和已有结果仍可恢复。
- 试用结果显示人工复核后确有时间节省或交付质量改善；若没有，应调整任务、输出结构或暂停该场景，而不是直接扩展更多办公集成。

## 下一步

先挑选少量获准使用的访谈材料，人工整理并记录基线。再做最小原型：输入一份材料、生成结构化简报、展示原文依据、允许编辑并导出。完成这一步前不接企业账号和外部写入接口。
